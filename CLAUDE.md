les parois intérieures s'arrêtent `GAP` = 0,6 mm sous la plaque basse (`innerHeights`) ; trou d'envol dans les deux faces avant (tunnel 2t + ins). **Tôle** (`metalSheet`, `material: 'metal'`) : plaque haute + rabat sur 4 côtés, coins échancrés, 4 plis en `lines` (gravure bleue). 15 pièces de contreplaqué + 1 tôle. `pieces()`, `layout(p, material)` (étagères, par matériau), `houseSvg(p, material)` (échelle réelle, noir = coupe y compris fentes, bleu = plis et noms ; la tôle a son propre SVG), `pieceSvg()`. `src/birdhouse/Birdhouse.tsx` : curseurs (Isolation, Tôle de toit avec bouton « gabarit de la tôle », dimensions, trou, contreplaqué, vue en coupe, liste de débit avec les bandes de laine à couper), vue 3D Three.js (y = hauteur, `camera.up` réglé à part car l'outil oiseau met `Object3D.DEFAULT_UP` sur Z ; pièces = `ExtrudeGeometry` du contour avec trous, arêtes tracées depuis le contour par `outline()` (pas `EdgesGeometry`, qui dessine les diagonales de triangulation) ; blocs de laine (`block`, avec tunnel optionnel pour le trou d'envol) (`block`, double face pour montrer la tranche en coupe) et tôle en boîtes ; le toit est un `Group` couché sur la pente (x en travers, y le long de la pente depuis l'avant, z vers le haut) où plaques, bords, laine et tôle sont placés en local ; attention aux repères directs pour `makeBasis` ; clic gauche ou molette = tourner, droit = déplacer ; section « Vue en coupe » : plan perpendiculaire à X/Y/Z à `offset` mm du centre (0, 150, 0), « Garder l'autre côté », `renderer.localClippingEnabled` + `material.clippingPlanes` sur les pièces seulement (`applyCut`, réappliqué à chaque reconstruction), plan dessiné en bleu transparent ; en dev, `window.__scene` expose la scène), panneau de droite « Pièces à découper » (`pieceSvg(piece, scale)` : chaque pièce seule, fentes en brun, plis en bleu pointillé, même échelle), vue « Planche à plat (2D) » (`Sheet2D` : clic droit / gauche + glisser = déplacer, roulette = zoom, Recadrer). Limites : haut des faces non biseauté selon la pente (~1 mm de jour), plancher simple (pas de laine dessous), pas de ventilation / drainage dessinés, pas de fixation arrière, pas de porte de nettoyage, pas de lame d'air ventilée entre tôle et caisson. Historique : simple paroi, balcon, double paroi sans toit isolé ont été essayés puis remplacés à la demande de l'utilisateur.

## Stack
Vite + React 19 + TypeScript + Tailwind v4 + Three.js. Alias `@/` → `src/`. Pas de store : l'état vit dans `App.tsx`.

## Architecture
- `src/engine/viewer.ts` : `StlViewer`, Three.js pur (aucune dépendance React, pas de sol). `load()` lit un STL ou un OBJ (`parseModel` : reconnu au contenu, binaire si la taille colle, sinon « solid » = STL ASCII, sinon OBJ fusionné en un seul maillage ; matériaux et normales ignorés), le centre, le met à l'échelle (plus grand côté = 2), rendu flat-shaded. `sync(models, selectedId)` pousse l'état dans la scène. Pipeline du maillage affiché : original → `simplify(target)` (mis en cache) ; dès qu'il y a une retouche à la main (`overrides`), **la réduction s'applique à ce qui reste** : `rebuild` appelle `resimplifyOverride`, qui réduit depuis `bases` (le maillage tel que retouché, avant sa dernière réduction ; cible 0 = tel que retouché) ; entrer en édition sans rien toucher ne crée pas de retouche ; `overrideState(id)` sert à enregistrer le maillage réduit ; « Tout rétablir » retombe sur l'original réduit. `rebuild(id, target)`. Mode édition : `setEdit(id, target)`, `setEditTool`, `undoEdit` ; outils sommet / arête / triangle (survol = surbrillance rouge, clic = suppression), `select` (polygone en pointillés posé clic par clic, calque SVG par-dessus la vue ; double-clic / Entrée / clic sur le premier point ferme, Échap abandonne, Maj ajoute ; triangles dont un sommet ou le centre tombe dans le polygone, ou qui contiennent un sommet du polygone ; écartés si un tampon de profondeur logiciel (demi-résolution, rastérisation de tous les triangles, coût linéaire) montre quelque chose devant leur centre, sauf `setSelectThrough` ; surbrillance orange), `plane` (plan bleu transparent orientable dans toutes les directions : `setPlane({offset, angle, tilt, diag1, diag2, horiz, keep})`, `planeQuaternion()` = Rx(horiz) · Rz(angle) · Ry(−tilt) · R(0,1,1)(diag1) · R(0,1,−1)(diag2) (`horiz` = inclinaison autour de l'axe horizontal X de la scène) appliqué au carré de base (normale X, diagonales (0,1,±1)/√2 dessinées sur le carré), normale = X tourné, triangles teintés vert = gardés / rouge = supprimés selon leur centre ; `traceSection(on)` : trait rouge de l'intersection plan/modèle, segments enchaînés en contours, bouts ouverts (trous) pontés par une courbe de Hermite qui prolonge les tangentes (`bridge`), recalculé à chaque mouvement du plan ; `keepTrace()` : copie en rouge sombre attachée au mesh (visible hors édition), `removeTrace(id, i)`, `clearTraces(id, announce)`, `setTraces` / `exportTraces`, `generateTraces(axe X|Y|Z|D1|D2, pas°)` : un plan par pas autour de l'axe (X/Y/Z par le centre du modèle ; D1/D2 = diagonales du plan courant, par le centre du plan, premier trait = plan courant), chaque intersection gardée (`sectionLines(n, d)` factorise le calcul des contours) ; événement `onTraces(id, Float32Array[])` → `putTraces` dans IndexedDB (`<id>:traces`), rechargés au démarrage) ; `exportSelectionStl()` : seuls les triangles sélectionnés en STL binaire (bouton « Exporter la sélection en STL », fichier `<nom>-selection-<N>tri.stl`, modèle intact) ; `deleteSelection()` retire le cadre ou le côté rouge, `pendingDelete` en donne le nombre ; `mirrorAcrossPlane()` supprime le rouge puis `EditMesh.mirror()` : sommets du bord de coupe ramenés sur le plan (à moins de 1,5 × arête médiane), triangles couchés dans le plan retirés, copie miroir à orientation inversée partageant les sommets du plan ; événements `onEdit(id, triangles, positions)`, `onSelect(count)`, `onMessage`. `paintPieces` colore les triangles par pièce du patron (vertexColors). `exportStl` : maillage affiché en STL binaire.
- `src/engine/simplify.ts` : réduction par regroupement de sommets sur une grille (vertex clustering, déterministe, dichotomie sur la taille de cellule).
- `src/engine/loft.ts` : `loftFromPlanes(pos, planes, N)` : reconstruit un modèle fermé depuis des coupes parallèles (la famille A de la gaufre) : boucle extérieure la plus grande de chaque coupe, ré-échantillonnée en N points depuis une direction commune, anneaux reliés par des quads, bouts fermés en éventail, orientation par volume signé. Limite : les parties séparées (pattes, branche) disparaissent, une section très concave peut se tordre. Côté viewer : `wireFromPlanes(id, planes)` (contours exacts de toutes les coupes, gardé comme un trait) `undoWire(id)` / `wireCount(id)` (bouton « Annuler le fil de fer » : retire le dernier fil de fer tracé et réaffiche le modèle ; le suivi des fils de fer n'est pas enregistré, après rechargement ce sont de simples traits avec leur ×) et `setModelHidden(id, hidden)` (cache la surface, garde les traits) ; dans le bloc « Gaufre automatique » : « Fil de fer : directions A et B » et « Fil de fer : les 3 axes X, Y et Z » (`makeWire(m, all3)`, mêmes pas et hauteur réelle), case « Cacher le modèle » (masque le matériau du modèle, que partage l'aperçu : générer un aperçu — loft ou tranches — la décoche automatiquement) et « Reconstruire le modèle 3D depuis le fil de fer » (curseur « Coupes pour la reconstruction », 24 par défaut, répartis sur toute la longueur du modèle dans la direction A, indépendant du pas de la gaufre ; erreurs et succès affichés sous le bouton, sans disparaître ; bouton « Exporter le STL reconstruit (N cm) » : `exportStl(id, false, mmPerUnit)`, STL binaire **à l'échelle réelle en millimètres** d'après la « hauteur réelle du modèle », nommé `<nom>-reconstruit-<N>cm-<tri>tri.stl`).
- `src/engine/meshEdit.ts` : `EditMesh` (sommets soudés + triangles indexés) : `removeVertex` (retriangule le trou par découpage d'oreilles, n → n − 2), `collapseEdge` (fusion au milieu, − 2 triangles), suppression directe d'un triangle = `tris.splice`.
- `src/engine/slices.ts` : tranches pour découpe laser. `sectionContours(pos, n, d)` (contours fermés de l'intersection plan/maillage, trous pontés par Hermite), `buildSlices(pos, planes, {mmPerUnit, thickness, wall})` : une tranche par plan (un plan par trait gardé, via `StlViewer.tracePlanes`), contours simplifiés (Douglas-Peucker 0,15 mm), creusés par décalage intérieur (`inset`, onglets limités, points trop près du bord retirés), rangées sur des planches A4 ; `sliceSvg` / `slicesHtml` (noir 0,1 mm = coupe, bleu = gravure, lien SVG par planche) ; `slicesGeometry` : aperçu 3D (ExtrudeGeometry par tranche, trous = `Shape.holes`, encoches non représentées). Mode « gaufre » (`makeWaffle` dans `App.tsx`) : deux familles de plans parallèles (directions X/Y/Z, un plan tous les N mm, `family` 0 / 1), `notch()` calcule à chaque croisement les encoches à mi-bois le long de la droite d'intersection des deux plans (intervalles de matière communs, A entaillée du côté t1 jusqu'au milieu, B du milieu au côté t2, largeur = épaisseur) ; les rectangles d'encoche dépassent du bord d'1 mm et sont coupés comme le reste. Les tranches « une par trait » n'ont pas d'encoches.
- `src/engine/unfold.ts` + `src/engine/pattern.ts` : **patron papier en polygones** (pas cintré). `unfold(geo, {maxTris, maxExtent})` : soude les sommets, part du plus grand triangle, pose chaque voisin par l'arête commune en choisissant celui qui agrandit le moins la pièce, écarte ce qui chevauche (séparation d'axes) ou dépasse la page ; plis montagne / vallée / plat ; arêtes coupées numérotées par paire, languette d'un seul côté. `layoutPattern(u, mmPerUnit, tabMm)` : mm, languettes trapézoïdales, rangement en étagères A4, longueurs à couper / plier. `pageSvg` / `printHtml` : noir = couper, bleu = pli montagne, violet = pli vallée, orange = numéros ; plis en trait plein (rainurage) ou en pointillés 1 mm / 1 mm (perforation) ; lien SVG sans teinte par planche pour le laser. Limité à 800 triangles (idéal 150 à 300). Onglet « Papier » : réduire, régler (hauteur réelle, languettes, triangles par pièce, style de pli), générer ; les pièces sont colorées sur le modèle (`paintPieces`), « Retirer les couleurs » les enlève.
- Affichage : quand un modèle est sélectionné, **les autres sont cachés automatiquement** (`mesh.visible = !selectedId || id === selectedId` dans `sync`) ; sans sélection, tous sont visibles. Pas de bouton « caché ».
- Sessions (`persist.ts`) : chaque fichier chargé a une session au **nom généré** (fichier1, fichier2…, `ensureSession`), non supprimable tant qu'elle est ouverte ; elle garde le fichier (IndexedDB, par nom), les retouches, les traits et les réglages. Fermer un modèle (×) la laisse enregistrée ; « Sessions fermées » la rouvre (`openSession`) ou la supprime pour de bon après confirmation (`deleteSession` : liste, réglages, fichier, retouches, traits, annulation). « Annuler tout ce que j'ai fait » (onglet Modèle, `cancelSession`) revient au fichier d'origine **après avoir gardé l'état d'avant** (`putSnapshot`, clé `n:<nom>:snap`) ; « Reprendre ma session d'avant l'annulation » (`resumeSession`) le remet.
- **Retour** (`App.tsx`) : bouton « ↶ Retour » en haut à gauche de la vue (comme l'éclairage en haut à droite) et Ctrl+Z : `backStack` annule la dernière action quelle qu'elle soit (retouche du maillage via `undoEdit`, réglages du modèle passés par `update()` — un curseur qu'on fait glisser = une action —, traits ajoutés / retirés, aperçu de tranches). Les entrées qui ne valent plus (retouche hors mode édition) sont sautées. Les retouches faites avant de quitter le mode édition ne s'annulent plus ensuite.
- Éclairage : `StlViewer.setLighting(preset)` avec 6 préréglages (`LIGHTING` : Studio, Doux, Contraste, Dessus, Frontal = lampe qui suit la caméra, Sombre = fond foncé) qui règlent lumière ambiante, lumière directionnelle et fond ; boutons en haut à droite de la vue, choix gardé dans localStorage (`visionneuse-stl-eclairage`).
- `src/ui/kit.tsx` : composants d'interface partagés : `Btn` (primary / secondary / danger / warn / ghost), `Chip`, `Section` (repliable : titre-bouton avec chevron ▸, **état ouvert / replié gardé dans localStorage `ui-section:<titre>`** — un titre qui change (nom de plaque) casserait la mémoire, d'où des titres fixes avec le détail dans `note`), `Hint`, `Notice`, `Tabs`. **Interface en 4 onglets** : Modèle (maillage, orientation et position, axes et plans, affichage), Édition (mode édition, outils, traits de coupe, actions faites), Coupes (réglages, gaufre, tranches par trait, fil de fer et reconstruction : le fil de fer a ses propres réglages — axes X/Y/Z et coupes par axe — et la reconstruction sa propre direction, rien en commun avec la gaufre), Papier. La liste des modèles et le bandeau « Annuler l'aperçu » restent au-dessus des onglets.
- `src/engine/meshEdit.ts` : soudure des sommets par table de hachage numérique (cellule de 10 µm, vérification exacte) : 292 000 triangles en ~1 s.
- `src/store/persist.ts` : **tout est enregistré automatiquement, par NOM de fichier** (plus de bouton Enregistrer) : redéposer un fichier de même nom le remet où on l'avait laissé. localStorage : liste de la session (`visionneuse-stl-modeles`) et réglages par nom (`visionneuse-stl-etats` : réduction, rotation, position, taille, couleur). IndexedDB (`visionneuse-stl` / `fichiers`) : octets du fichier par id de session, retouches `n:<nom>:edit` (cible + sommets) et traits `n:<nom>:traces`. `restoreWork(v, m)` (App.tsx) réapplique retouches, réduction et traits au chargement (session ou dépôt) ; migration automatique des anciennes clés par id. Retirer un modèle de la liste ne efface pas son travail ; « Tout rétablir » efface ses retouches.
- `src/App.tsx` : panneau (modèles ; maillage : triangles visés, préréglages, téléchargement ; édition à la main (sans limite de taille ; avertissement au-delà de 100 000 triangles, historique réduit à 15 étapes au-delà de 20 000) : outils sommet / arête / triangle / sélection polygonale (Maj : ajoute, case « faces cachées ») / plan de coupe vertical (position, orientation, côté gardé, symétrie), suppression par bouton ou touche Suppr, liste « Actions faites » avec un bouton Annuler par action (`undoTo(i)` : annule cette action et les suivantes ; `onHistory(labels)`), Ctrl+Z, tout rétablir ; préréglages de réduction 1 000 → 100 par pas de 100 ; tranches pour découpe laser (hauteur réelle, épaisseur du matériau, creuses + largeur de paroi, « Générer les tranches » = une par trait gardé, aperçu 3D remplaçant le maillage jusqu'à « Revenir au modèle », planches SVG) ; affichage : taille à l'écran, couleur) et dépôt de fichiers (glisser-déposer sur toute la fenêtre ou bouton). La réduction est recalculée 150 ms après le dernier changement de cible (`geoKey`). Restauration de la dernière session au démarrage.
- `src/ui/Slider.tsx` : curseur à valeur éditable au clavier (repris de l'archive), avec boutons − / + (un pas, Maj : dix pas) ; prop `marks` = repères cliquables sous le curseur (trait + nom, ex. « milieu » sur la position d'un trou).
- Section « Axes et plans » : par axe X / Y / Z, case « afficher » (axe général dans la vue, `setAxisVisible`) et case « activer » (plan ⟂ à l'axe, **fixe à l'origine des axes**, carré transparent + ligne de coupe rouge sur le modèle sélectionné, recalculée dans `sync()` via `updateWorldPlanes` quand le modèle bouge, tourne ou change de maillage : on déplace le modèle à travers le plan). Ces plans ne modifient rien ; ce sont des repères.

## Conventions de vue (comme dans l'archive)
- Repère : X = droite, Y = profondeur, Z = haut (`Object3D.DEFAULT_UP = (0,0,1)`).
- Caméra : clic gauche ou molette = tourner, clic droit = déplacer, roulette = zoom. Un clic sans glissé sur un modèle le sélectionne (hors mode édition).
- Les modèles sont rangés côte à côte à l'import (pas de déplacement), mais ils se **tournent** sur les trois axes (`ModelState.rot`, degrés XYZ, curseurs « Orientation et affichage »). La rotation reste une transformation du mesh (géométrie locale inchangée) : les outils d'édition, les traits et les tranches par trait travaillent en local ; la gaufre convertit les plans X/Y/Z de l'écran en local (`waffleLocalPlanes` : un plan sur l'axe lui-même, c'est-à-dire par l'origine de la scène, puis un tous les N mm vers chaque côté tant que le modèle est traversé ; la position du modèle compte, sa taille à l'écran non), la hauteur réelle utilise `rotatedSizeOf`, et `exportStl` applique la rotation. Position par curseurs X/Y/Z (jamais à la souris). Axes généraux dessinés dans la scène : X rouge, Y vert, Z bleu (hauteur), avec leur lettre en sprite.
- Matériau double face (`DoubleSide`) : après une suppression de triangles, l'intérieur se lit comme une surface, pas comme des arêtes flottantes.
- Vite sous Windows perd parfois un événement de modification quand deux éditions d'un même fichier sont très rapprochées : si le navigateur semble ignorer un changement, `touch` le fichier (ou relancer `npm run dev`).
- localStorage et IndexedDB sont partagés entre tous les onglets ouverts sur `localhost:5174` : deux onglets qui modifient la liste des modèles s'écrasent l'un l'autre.

## Limites connues
- Tranches creuses : le décalage intérieur est approximatif dans les pointes étroites (points trop près du bord retirés, pas de vrai calcul d'offset).
- Les tranches « une par trait » n'ont pas d'encoches ; seul le mode gaufre (deux familles parallèles) en calcule.
- La réduction par grille ne préserve pas les arêtes vives.
- Un fichier de plus de 10 Mo ne passe pas par le pont de test du navigateur de Claude ; dans Chrome il se charge normalement.
